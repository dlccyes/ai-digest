## The problem in plain language

Two strings describe the same row of spaces. Each nonblank character is a piece: `L` may slide only to the left, `R` may slide only to the right, and `_` is an empty position. A move slides one piece by one position into an adjacent blank. The question is whether repeated legal moves can turn `start` into `target`.

The important restriction is not the number of blanks. It is that pieces cannot jump over one another. Every move swaps a piece with a blank, so the left-to-right order of all `L` and `R` pieces must remain unchanged.

## Deriving the optimal solution

Imagine erasing every underscore from both strings. If the remaining piece sequences differ, the transformation is impossible: matching counts are not enough because no two pieces can cross. For example, `L_R` cannot become `R_L` even though both strings contain one piece of each type.

If the sequences match, pair each piece in `start` with the corresponding piece in `target`. Only its direction remains to be checked:

- An `L` piece may finish at the same index or a smaller index. If its target index is greater than its start index, it would have to move right.
- An `R` piece may finish at the same index or a greater index. If its target index is smaller than its start index, it would have to move left.

These conditions are also sufficient. Matching the nonblank sequences preserves the order of the pieces, while each index check says that its matched destination lies in its permitted direction. The intervening characters that are not pieces in that preserved order are blanks, so the pieces can be slid to their destinations without a crossing. One constructive order is to settle left-moving pieces from left to right and right-moving pieces from right to left; pieces already settled cannot obstruct the remaining moves.

There is no need to build the underscore-free strings. Two pointers can skip blanks in both inputs, compare the next pieces, and check their indices immediately. Each pointer moves only forward, so the algorithm takes `O(n)` time and `O(1)` extra space.

For `start = "_L__R__R_"` and `target = "L______RR"`, both nonblank sequences are `LRR`. The `L` moves from index `1` to `0`, and the two `R` pieces move from indices `4` and `7` to `7` and `8`. Every move is in the permitted direction, so the transformation is possible.

## Python solution

```python
class Solution:
    def canChange(self, start: str, target: str) -> bool:
        """Return whether legal one-directional slides can reach target."""
        if len(start) != len(target):
            return False

        length = len(start)
        start_index = 0
        target_index = 0

        while start_index < length or target_index < length:
            # Find the next actual piece in each configuration.
            while start_index < length and start[start_index] == "_":
                start_index += 1
            while target_index < length and target[target_index] == "_":
                target_index += 1

            # Both sequences of pieces have ended successfully.
            if start_index == length and target_index == length:
                return True

            # Only one sequence ended, so the piece counts differ.
            if start_index == length or target_index == length:
                return False

            piece = start[start_index]
            if piece != target[target_index]:
                return False

            # L cannot move right, and R cannot move left.
            if piece == "L" and start_index < target_index:
                return False
            if piece == "R" and start_index > target_index:
                return False

            start_index += 1
            target_index += 1

        return True
```

## Why the algorithm is correct

Each move exchanges a piece with an underscore. It therefore never changes the relative order of the nonblank pieces. The algorithm rejects exactly when the two strings have different nonblank sequences, including the case where one sequence has extra pieces.

For corresponding pieces in the same preserved sequence, an `L` can reach only an index no greater than its original index, and an `R` can reach only an index no smaller than its original index. The algorithm checks both necessary inequalities and rejects every directional violation.

Conversely, suppose the nonblank sequences match and all paired indices obey their direction inequalities. No paired pieces need to cross, and every piece's destination is on its allowed side. Sliding left-moving pieces from left to right and right-moving pieces from right to left supplies the required blanks without disturbing a settled piece. Thus a legal sequence of moves exists. The algorithm returns `True` exactly for reachable targets.

## Interview follow-ups

### Could this be solved by deleting the underscores first?

Yes. Comparing `start.replace("_", "")` with `target.replace("_", "")` verifies that piece order is unchanged, and a second pass can check each matched piece's original and target indices. That version is often shorter, but it allocates `O(n)` extra space for the filtered strings or index lists. The two-pointer solution performs the same checks online with `O(1)` auxiliary space.

### How would you return the minimum number of moves?

If the transformation is valid, each piece has only one permitted direction and must travel exactly the distance between its matched start and target indices. Every legal move changes one piece's position by one, so the minimum number of moves is the sum of those absolute distances. The same scan can accumulate that sum after the order and direction checks, preserving `O(n)` time and `O(1)` extra space.

### How would you output an actual sequence of moves?

First run the feasibility check. Then settle `L` pieces from left to right by repeatedly sliding each one left until it reaches its matched target index. After that, settle `R` pieces from right to left by sliding each one right. This order avoids trapping a piece behind another piece that has not yet moved. Reporting the sequence takes `O(n + m)` time, where `m` is the number of individual moves, and the output itself requires `O(m)` space.

### What changes if both piece types may move in both directions?

Direction inequalities disappear. If pieces still cannot jump over one another and pieces of the same letter are indistinguishable, matching nonblank sequences becomes the complete feasibility test. If jumping or swapping pieces is allowed as well, even the order constraint may disappear, and comparing the counts of each piece type may be sufficient depending on the exact operation.

### What if `L` and `R` have different movement costs?

Feasibility is unchanged because costs do not change which moves are legal. Once corresponding pieces are matched in their preserved order, multiply each traveled distance by that piece type's per-step cost and sum the results. This remains optimal because every piece must cover that exact distance and cannot trade movement with another piece.

### What edge cases should be tested?

Important cases include identical strings, strings containing only underscores, one side having an extra piece, the same piece counts in a different order, an `L` forced right, an `R` forced left, and pieces that move all the way to an endpoint. The official examples are useful because they separately exercise a reachable transformation, an order conflict, and a directional conflict.
