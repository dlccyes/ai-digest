## The problem in plain language

Given a binary string, count its substrings whose number of `1` characters is at least the square of the number of `0` characters. If a substring contains $z$ zeros and $o$ ones, it qualifies when

\[
o \ge z^2.
\]

Trying every pair of endpoints takes quadratic time. The square in the condition supplies the way out: a valid substring with $z$ zeros must have length at least

\[
z + z^2.
\]

Because the entire string has length $n$, a valid substring can contain only $O(\sqrt n)$ zeros. That lets the algorithm enumerate possible zero counts instead of all possible right endpoints.

## Deriving the counting method

Fix a left endpoint. First consider substrings with no zeros. If the next zero is at position $p$, every right endpoint from the left endpoint through $p - 1$ forms an all-ones substring, so this case contributes $p - \text{left}$.

Now suppose the substring must contain exactly $z \ge 1$ zeros. Let the $z$-th zero at or after the left endpoint be at position $p_z$, and let the following zero be at $p_{z+1}$. A right endpoint produces exactly $z$ zeros precisely when it lies in

\[
[p_z, p_{z+1} - 1].
\]

The dominance condition also requires a total length of at least $z^2 + z$, so the right endpoint must be at least

\[
\text{left} + z^2 + z - 1.
\]

Therefore, the first valid right endpoint for this zero count is

\[
\max(p_z,\; \text{left} + z^2 + z - 1).
\]

Every endpoint from there through $p_{z+1} - 1$ is valid. Storing all zero positions, plus $n$ as a sentinel, makes both boundaries available in constant time. For each left endpoint, the loop stops once $z^2 + z$ exceeds the remaining string length.

### Why this counts every valid substring exactly once

Each substring has one left endpoint and one exact number of zeros. For that pair, its right endpoint falls into exactly one interval between consecutive zero positions. The length threshold removes precisely the endpoints that do not contain enough ones. No substring can enter two cases, and every dominant substring enters its unique case.

### Complexity

For each of $n$ left endpoints, at most $O(\sqrt n)$ zero counts are possible. The time complexity is $O(n\sqrt n)$, and the zero-position array uses $O(n)$ space in the worst case.

## Python solution

```python
class Solution:
    @staticmethod
    def _minimum_dominant_length(zero_count: int) -> int:
        """Return the shortest length that can dominate with zero_count zeros."""
        return zero_count * zero_count + zero_count

    def numberOfSubstrings(self, s: str) -> int:
        """Count substrings whose ones count is at least the zeros count squared."""
        length = len(s)

        # The sentinel acts as the zero immediately after the end of the string.
        zero_positions = [index for index, bit in enumerate(s) if bit == "0"]
        zero_positions.append(length)

        dominant_substrings = 0
        first_available_zero = 0

        for left in range(length):
            # Move to the first zero that is not left of this substring.
            while zero_positions[first_available_zero] < left:
                first_available_zero += 1

            # Every endpoint before the first zero gives an all-ones substring.
            dominant_substrings += zero_positions[first_available_zero] - left

            zero_slot = first_available_zero
            zero_count = 1

            while zero_slot < len(zero_positions) - 1:
                minimum_length = self._minimum_dominant_length(zero_count)
                if minimum_length > length - left:
                    break

                current_zero = zero_positions[zero_slot]
                next_zero = zero_positions[zero_slot + 1]

                # End at or after both the z-th zero and the length threshold,
                # but before the next zero so the substring has exactly z zeros.
                first_valid_right = max(
                    current_zero,
                    left + minimum_length - 1,
                )
                if first_valid_right < next_zero:
                    dominant_substrings += next_zero - first_valid_right

                zero_slot += 1
                zero_count += 1

        return dominant_substrings
```

## Interview follow-ups

### Why does a normal sliding window not work?

A classic sliding window needs validity to change monotonically as one boundary moves. Here, extending a substring with `1` helps, but extending it with `0` can abruptly raise the required number of ones from $z^2$ to $(z+1)^2$. A valid window can become invalid and later become valid again, so there is no single left boundary that separates all valid windows from all invalid ones. Enumerating the small number of possible zero counts restores a useful structure.

### Could the algorithm enumerate right endpoints instead?

Yes. Fix a right endpoint, walk backward through the most recent zero positions, and count ranges of left endpoints that give exactly $z$ zeros and enough ones. The same bound $z = O(\sqrt n)$ applies, so the asymptotic complexity remains $O(n\sqrt n)$. The forward version is often easier to explain because each interval of right endpoints is directly bounded by two consecutive zeros.

### How would the solution change for ones greater than or equal to $c z^2$?

Only the minimum-length formula changes. With $z$ zeros, the substring needs at least $c z^2$ ones, so its exact minimum length becomes $z + \lceil c z^2 \rceil$. The same zero-position intervals work. For a fixed positive $c$, at most $O(\sqrt{n/c})$ zero counts need consideration per left endpoint, which preserves the $O(n\sqrt n)$ worst-case form.

### What if the requirement were linear, such as ones greater than or equal to $c z$?

Assign each `1` a weight of $1$ and each `0` a weight of $-c$. A substring is valid exactly when its weighted sum is nonnegative. Prefix sums then turn the task into counting ordered pairs whose later prefix is at least the earlier prefix. Coordinate compression with a Fenwick tree can count those pairs in $O(n \log n)$ time and $O(n)$ space. The quadratic condition cannot be reduced to one fixed per-character weight because the cost of another zero depends on how many zeros are already present.

### Can the memory usage be reduced?

The presented method stores only zero positions, so its space is $O(m)$, where $m$ is the number of zeros, rather than always $O(n)$. Replacing the list with repeated scans would reduce auxiliary storage but can make the running time quadratic. A right-to-left variant can maintain a bounded collection of recent zeros for each right endpoint, but it complicates indexing without improving the $O(n\sqrt n)$ time bound.

### How would the algorithm return the substrings themselves?

Whenever a zero-count case yields the valid endpoint interval $[a, b]$, emit every pair `(left, right)` for `right` from $a$ through $b$. The counting logic does not change. The running time becomes $O(n\sqrt n + R)$, where $R$ is the number of returned substrings, which is optimal up to the counting overhead because producing $R$ results already costs $O(R)$.
