## The problem in one picture

Imagine hanging the tree from any node and looking upward from the leaves. Each subtree has a total value. If that total is divisible by `k`, the edge to its parent can be cut and the entire subtree becomes one valid component.

The goal is to make as many such cuts as possible while ensuring that every final component has a sum divisible by `k`. The input guarantees that the sum of the whole tree is divisible by `k`, so at least the uncut tree is valid.

## Deriving the greedy postorder solution

Root the tree at node `0`. A node cannot decide whether its subtree is a complete component until all of its children have been processed, so the natural traversal order is postorder.

For each subtree, only one fact matters to its parent: its sum modulo `k`.

- If the remainder is zero, count that subtree as a component and pass nothing upward. Cutting it cannot hurt the rest of the tree because removing a multiple of `k` does not change the remainder of what remains.
- If the remainder is nonzero, the subtree cannot stand alone. Pass its remainder to the parent, where it may combine with other values to form a divisible component.

This greedy cut is always safe. Suppose a subtree sum is divisible by `k`. Any valid solution that keeps it attached to its parent can instead cut the connecting edge. The detached subtree is valid, and the parent-side sum loses a multiple of `k`, so its divisibility is unchanged. The modified solution has one more component. Therefore an optimal solution cuts every divisible subtree as soon as postorder processing finds it.

An iterative traversal avoids Python's recursion-depth limit on a long, chain-shaped tree. A first pass records each node after its parent; reading that order backward gives children before parents.

## Python solution

```python
from typing import List, Tuple


class Solution:
    def maxKDivisibleComponents(
        self,
        n: int,
        edges: List[List[int]],
        values: List[int],
        k: int,
    ) -> int:
        adjacency = [[] for _ in range(n)]
        for first_node, second_node in edges:
            adjacency[first_node].append(second_node)
            adjacency[second_node].append(first_node)

        parent, traversal_order = self._root_tree(adjacency)
        subtree_remainder = [value % k for value in values]
        component_count = 0

        # Reverse discovery order is a postorder because every parent was
        # discovered before each of its children.
        for node in reversed(traversal_order):
            if subtree_remainder[node] == 0:
                # This subtree is a complete component, so none of its sum
                # needs to be carried into the parent component.
                component_count += 1
                continue

            parent_node = parent[node]
            if parent_node != -1:
                subtree_remainder[parent_node] = (
                    subtree_remainder[parent_node] + subtree_remainder[node]
                ) % k

        return component_count

    @staticmethod
    def _root_tree(adjacency: List[List[int]]) -> Tuple[List[int], List[int]]:
        parent = [-2] * len(adjacency)
        parent[0] = -1
        traversal_order = []
        stack = [0]

        while stack:
            node = stack.pop()
            traversal_order.append(node)

            for neighbor in adjacency[node]:
                if parent[neighbor] != -2:
                    continue
                parent[neighbor] = node
                stack.append(neighbor)

        return parent, traversal_order
```

Building the adjacency list and processing the tree both take `O(n)` time. The adjacency list, parent array, traversal order, remainder array, and stack use `O(n)` space.

## Interview follow-ups

### Why is it enough to pass only a remainder to the parent?

Divisibility by `k` depends only on the remainder. If two subtree sums have the same remainder modulo `k`, adding either one to the parent produces the same divisibility result. Keeping remainders also prevents intermediate sums from growing unnecessarily, although Python integers would still remain correct.

### How would the solution return the edges that should be removed?

During the reverse traversal, whenever a non-root node has remainder zero, record the edge from that node to `parent[node]`. That edge separates the newly counted component. The component count remains the same, and recording at most `n - 1` edges does not change the `O(n)` time or space bounds.

### Could this be written with recursive DFS?

Yes. A recursive function can return each subtree's remainder and increment the answer whenever that remainder is zero. The reasoning and `O(n)` complexity are identical. The iterative form is safer in Python because a tree may be a long chain, making recursion exceed the interpreter's default stack limit.

### What if the total tree sum is not divisible by `k`?

Then no split can make every component divisible by `k`: the sum of several multiples of `k` must itself be a multiple of `k`. A production API without the problem's guarantee should check `sum(values) % k` first and return an agreed sentinel, such as `0` or `-1`, or raise an exception. The traversal itself does not need to change.

### Does the choice of root affect the maximum answer?

No. Rooting only gives the algorithm a direction in which to aggregate subtree sums. Every cut still refers to an ordinary undirected edge, and the safe-cut argument applies regardless of which endpoint is considered the child. Different roots may discover the components in a different order, but they produce the same maximum count.

### What changes if node values can be negative?

Nothing essential. Modular addition still works, and a remainder of zero still means that the exact subtree sum is divisible by `k`. The implementation already normalizes every value with Python's `%` operator, so negative values map to consistent remainders from `0` through `k - 1`.
