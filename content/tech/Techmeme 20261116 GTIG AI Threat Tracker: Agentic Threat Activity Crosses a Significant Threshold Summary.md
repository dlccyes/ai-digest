[Techmeme surfaced](https://www.techmeme.com/261116/p30) Google Threat Intelligence Group and Mandiant’s November 16 report, [“GTIG AI Threat Tracker: Agentic Threat Activity Crosses a Significant Threshold.”](https://cloud.google.com/blog/topics/threat-intelligence/agentic-threat-activity-crosses-a-significant-threshold) Its most consequential finding is an exposed framework configured to continuously compare software before and after security patches, infer the repaired vulnerability, draft an exploit, and run it without waiting for a person to approve each step. The report calls this GTIG’s first observation of threat actors fully automating vulnerability discovery and exploitation without a human in the loop.

## A patch became the specification for an attack

GTIG found the framework on an exposed staging server and named it `exploit_agent`. It connected multiple frontier and locally hosted language models to a multi-agent workflow aimed at popular web applications. Instead of searching all possible code for an unknown zero-day, the system watched a much smaller and more informative target: the difference between code before and after a patch announcement.

That difference can reveal exactly where maintainers changed an authorization check, parser, or memory operation. `exploit_agent` analyzed those changes, formed vulnerability hypotheses, generated exploit code, and executed it automatically. One artifact showed it examining an access-control implementation in version 2.19.25 of the Spectra WordPress plugin. Russian-language comments in a configuration file instructed the operator to enter API keys for the automated-exploitation pilot, but GTIG did not identify the operator or attribute the activity to a country.

The same server held data exfiltrated from victims and scripts for internal reconnaissance, brute-force attempts, webshell installation, and removal of other attackers’ webshells. Victim telemetry indicated a focus on French media, entertainment, and education sites. Those artifacts make this more than a laboratory demonstration. They do not, however, provide a public, step-by-step forensic record tying every successful intrusion to a specific model-generated exploit.

The phrase “without a human in the loop” also needs a boundary. Human setup was still required: the framework had to be configured, directed at software, and connected to models. The new capability is that a person did not have to inspect each patch, write each proof of concept, or authorize each execution. Once established, the pipeline could repeat that work continuously.

## N-days are the economical target

The system’s choice of patched vulnerabilities is important. A zero-day search asks an agent to find an unknown flaw somewhere in a large codebase. An n-day search begins after a fix or disclosure has narrowed the problem. Source diffs, preview builds, release notes, public research, and proof-of-concept code reduce the search space and give an automated system immediate feedback.

That changes the meaning of a patch release. A fix still protects users who install it, but it can simultaneously become a high-quality clue for attacking users who do not. The vulnerable interval is therefore no longer just the time between discovery and publication. It includes the delay between publication and actual deployment across internet-facing systems.

GTIG connects this mechanism to several recent cases without claiming that all were run by `exploit_agent`. After two PaperCut flaws were disclosed, security researchers and Huntress generated working exploits with language models within a day. GreyNoise then observed a campaign four days after disclosure that likely used language models to build and test exploits, assemble targets, and attack hundreds of organizations. In a separate PHP case, early patched code appeared before the official October 21 release, while the days after publication produced hundreds of claimed but nonfunctional proofs of concept that defenders had to verify or reject.

The latter failure mode matters. Language models do not merely accelerate real exploits; they also produce convincing junk at scale. Defenders may have to distinguish a working weapon from a hallucinated one while simultaneously patching systems and investigating live traffic. Automation reduces the attacker’s cost of trying many candidates even when most candidates fail.

## Speed currently comes with noise

The broader report describes open-source frameworks such as CAIRN, CyberStrikeAI, HexStrike AI, and PentAGI coordinating models with ordinary security tools. GTIG observed CAIRN in intrusion activity that included a US aerospace target and tracked a customized PentAGI-based platform scanning organizations across Asia. These systems can connect reconnaissance, payload generation, execution feedback, and tactical adjustment without requiring an expert to operate each tool manually.

For now, autonomy has an operational weakness: it is noisy. GTIG says unrestricted execution creates large volumes of forensic traffic, uses recognizable identifiers, and leaves code-level traces. Models can also hallucinate targets or other details, reducing reliability. Highly disciplined espionage groups may therefore use agents selectively where speed matters, while criminals who value reach over stealth have more reason to accept lower success rates.

That tradeoff is not a durable defense. Models, harnesses, and operators can improve their filtering and operational security. More importantly, even a detectable system can succeed when it tests many exposed servers faster than defenders can inventory and patch them.

## Patch management becomes part of incident response

The defensive lesson is less exotic than the attacking machinery. Internet-facing software needs fast asset discovery, prompt patch deployment, strong isolation, useful behavioral telemetry, and controls that limit what a compromised service account can reach. Detection also has to look for the volume and sequencing of agentic activity rather than only familiar malware signatures. GTIG says Google Security Operations has deployed behavioral and volumetric rules for ARTEX, while Mandiant has published a hardening framework for LLM-enabled offensive tooling.

The report remains a vendor account based on Google and Mandiant telemetry. It does not publish the `exploit_agent` code, name the models it used, quantify its success rate, identify its operator, or release enough victim evidence for outsiders to reconstruct the campaign independently. Its “first” is specifically GTIG’s first observation, not proof that no earlier autonomous exploitation occurred elsewhere.

Even with those limits, the threshold is concrete. Automated exploit development has moved from benchmarks and defensive research pipelines into infrastructure associated with real victims. The strategic contest is no longer simply whether AI can find a vulnerability. It is whether defenders can validate, patch, deploy, detect, and contain at least as quickly as an unattended system can turn a public fix into the next attack.
